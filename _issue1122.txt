--- ongandrew 2026-01-28T06:19:34Z
I was able to get this working with Atelier Resleriana (Unity 2022.3.62f2) but can't confirm if it's a general fix.

It involves two parts:
1) `Logging.UnityLogListening` must be set to `false` in _BepInEx.cfg_.
2) Include this signature definition in _Il2CppInterop/Il2CppInterop.Runtime/Injection/InjectorHelpers.cs_ for

```
            new MemoryUtils.SignatureDefinition
            {
                pattern = "\x48\x8B\xC4\x48\x89\x58\x00\x48\x89\x68\x00\x48\x89\x70\x00\x57\x41\x56\x41\x57\x48\x83\xEC\x00",
                mask = "xxxxxx?xxx?xxx?xxxxxxxxx?",
                xref = false
            },
```

This was obtained by tracing through Ghidra + Il2CppDumper through the following path:

1. Locate exposed function il2cpp_runtime_class_init. It'll be a wrapper with a single JMP instruction.
2. Go to the location referenced by the JMP instruction, which is likely a thread-safe wrapper, and look for a CALL instruction that takes the class pointer. For this particular instance, it was the second CALL instruction.
3. Then in this next function being called (likely another wrapper), there were three CALL instructions, it was the second CALL instruciton again (the first and last seemed to just acquire and release locks).
4. Follow that CALL instruction - that turned out to be the Class::Init we were after.

I don't have any other IL2CPP Unity games on hand with this version or above, so I'll leave it to those that come after to formally test it on a wider range and do a pull request!
